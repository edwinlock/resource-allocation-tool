Slider Implementation Guide

Overview

The slider interface is used in the parent treatment sessions to collect resource allocation decisions. Parents use a slider to distribute a fixed budget (fichas/lessons) between two children and see the outcomes displayed in interactive charts.

Slider Configurations

The application uses three different slider configurations:

1. Practice Slider 1 (practice-v1)

File: scenarios/scenarios-dummy.json

  • Purpose: First practice to familiarize parents with the slider interface
  • Context: Store analogy (Walmart vs Soriana)
  • Budget: 9 fichas
  • Scenarios: 1 scenario (σ=1, θ=2)
  • Pre-earnings gap: [5, 2]

2. Practice Slider 2 (practice-v2)

File: scenarios/scenarios-dummy-2.json

  • Purpose: Second practice (only shown if user didn’t allocate optimally in Practice 1)
  • Context: Store analogy (Walmart vs Soriana)
  • Budget: 9 fichas
  • Scenarios: 1 scenario
  • Conditional display: Skipped if user allocated all budget to high child in Practice 1

3. Main Slider (main-v1)

File: scenarios/scenarios.json

  • Purpose: Actual experimental data collection
  • Context: Real children (uses actual child names from session)
  • Budget: 9 fichas
  • Scenarios: 6 different economic scenarios
  • Pre-earnings gaps: Varies by scenario ([5,2], [4,3], [6,1])

Treatment Parent Workflow

The complete workflow for treatment parents:

  1. Treatment Survey - Initial demographic and attitudinal questions
  2. Practice Slider 1 (practice-v1) - First practice with store analogy
  3. Practice Slider 2 (practice-v2) - Second practice (conditionally shown)
  4. Sandwich Survey - Intermediate survey between practice and real sliders
  5. Main Slider (main-v1) - Actual experiment with 6 scenarios
  6. Exit Survey - Final questions

Conditional Skip Logic for Practice Slider 2

Practice Slider 2 is automatically skipped if the user allocates optimally in Practice Slider 1.

Optimal allocation = All allocatable_budget fichas to the high-performing child: - If child 1 is high → child1investment === allocatable_budget (all 9 fichas to child 1) - If child 2 is high → child1investment === 0 (all 9 fichas to child 2)

Implementation: isOptimalAllocation() method in js/modules/ui-slider.js

Randomization Per Scenario

For each scenario, the system performs cryptographically secure randomization to ensure unbiased experimental conditions.

The Coin Flip

Location: js/modules/app-state.js - computeScenarioOutcomes() method

For each NEW scenario, a cryptographically secure random number generator determines which child is “high” vs “low”:

const randomBuffer = new Uint32Array(1);
crypto.getRandomValues(randomBuffer);
high_child = (randomBuffer[0] % 2) + 1;  // Returns 1 or 2

What Gets Randomized

1. Which Child is High Performer

The coin flip randomly assigns: - high_child = 1: Child 1 gets high pre-earnings, better returns - high_child = 2: Child 2 gets high pre-earnings, better returns

2. Pre-Earnings Assignment

Based on the scenario’s pre_earnings array (e.g., [5, 2]): - High child receives first value (5) - Low child receives second value (2)

3. Chart Colors

Location: js/modules/chart-factory.js - getChildColors() method

Colors are dynamically assigned based on the coin flip:

If high_child = 1 If high_child = 2
Child 1 → Orange (high) Child 1 → Green (low)
Child 2 → Green (low) Child 2 → Orange (high)
  • Orange (#ff7f0e): High performer
  • Green (#2ca02c): Low performer
  • Blue (#1f77b4): Combined/aggregate

4. Legend Order

The legend automatically adjusts to show children in the appropriate order based on which is high/low.

What Is NOT Randomized

Slider Physical Position

Important: The slider positions are fixed: - Left side: Always Child 1 - Right side: Always Child 2 - Slider value: Always represents investment in Child 1

The randomization determines which child (left or right position) is the high performer, not the physical arrangement of the slider.

Scenario Order Randomization

Location: js/modules/app-state.js - Constructor

The order in which scenarios are presented is randomized at the start of each slider session:

const scenarioOrder = [...Array(SCENARIOS.length).keys()];
// Fisher-Yates shuffle
for (let i = scenarioOrder.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [scenarioOrder[i], scenarioOrder[j]] = [scenarioOrder[j], scenarioOrder[i]];
}

Key Field: highChild

The highChild field (1 or 2) is critical for analysis: - Tells you which child had better returns in that scenario - Combined with child1investment, reveals if user favored the high or low child - Allows you to analyze investment patterns relative to child performance

Example Analysis:

If highChild = 1 and child1investment = 9:
  → User gave all to high performer

If highChild = 2 and child1investment = 9:
  → User gave all to low performer

Economic Model

The slider uses a CES (Constant Elasticity of Substitution) production function to compute outcomes.

Parameters

  • γ (gamma): Weight parameter (always 0.5 in current scenarios)
  • σ (sigma): Elasticity of substitution
    • σ = 0: Cobb-Douglas (multiplicative)
    • σ > 0: Greater substitutability
    • σ < 0: Complements
  • θ (theta): Returns to scale
    • θ = 1: Constant returns
    • θ = 2: Increasing returns

Computation

Location: js/modules/economic-engine.js

For each possible investment allocation (0-9), the system computes: 1. Child-specific outcomes 2. Aggregate household outcomes 3. Displays results in interactive charts

User Interface

Slider Component

  • Input: Range slider (0 to allocatable_budget)
  • Display: Shows current allocation for both children
  • Real-time updates: Charts update as slider moves
  • Validation: Must move slider before proceeding (prevents accidental skips)

Charts

Three chart types available (line charts are primary): 1. Line charts: Show outcomes across all possible allocations 2. Bar charts: Alternative visualization 3. Advanced view: Additional detail (hidden from parents)

Navigation

  • Previous button: Go back to previous scenario (preserves previous answer)
  • Next button: Confirm allocation and proceed
  • Progress indicator: Shows current scenario out of total

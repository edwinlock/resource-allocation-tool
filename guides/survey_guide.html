Survey JSON Format Guide

Basic Survey Structure

{
    "survey_id": "surveyName",
    "name": "Survey Display Title",
    "questions": [
        // Array of question objects
    ]
}

Variable Substitution

Use {variableName} in any text field to inject session data. Available variables depend on the session type.

Important: Variables are resolved when the survey is displayed AND when answers are stored: - Display: {child1name} appears as “José” to the user - Stored answer: Database contains “José”, not {child1name}

This applies to: - Question text (query, text, prefixes) - Answer choices (values, options) - Input prefixes (prefix field for open questions)

Variables Available for ALL Session Types

Variable Description Example
{sessionType} Session type “child” or “parent”
{enumerator} Enumerator ID 101
{familyId} Family ID “FAM001”
{school} School name “Escuela Primaria Benito Juárez”

Variables ONLY for Child Sessions (sessionType = “child”)

Variable Description Example
{childName} Child’s name “María”
{childId} Child’s ID within family “C1” or “C2”

⚠️ Important: In child surveys, you cannot use {child1name} or {child2name} since the session is for one child only.

Variables ONLY for Parent Sessions (sessionType = “parent”)

Variable Description Example
{child1name} First child’s name “María”
{child2name} Second child’s name “Carlos”
{preEarnings1} First child’s pre-earnings 1, 2, 5, or 6
{preEarnings2} Second child’s pre-earnings 1, 2, 5, or 6

Note: preEarnings values are always one of four pairs: [1,6], [2,5], [5,2], or [6,1]

Question Types

1. open - Single text/number input

Basic usage:

{
    "question_id": "unique_id",
    "type": "open",
    "query": "What is {child1name}'s favorite subject?",
    "datatype": "text",  // or "number"
    "required": true
}

Enhanced number input with prefix and decimal control:

{
    "question_id": "price_estimate",
    "type": "open",
    "query": "¿Cuánto estaría dispuesto a pagar?",
    "datatype": "number",
    "prefix": "$",                    // Optional: Shows prefix before input (e.g., "$", "€", "MXN")
    "decimal_places": 2,              // Optional: Controls decimal precision (0=integers, 2=currency, etc.)
    "comma_separated": true,          // Optional: Shows formatted number below input (e.g., "150,000.50")
    "required": true
}

Options for decimal_places: - 0 - Integers only (step=“1”): allows 0, 1, 100, etc. - 1 - One decimal place (step=“0.1”): allows 1.5, 2.3, etc. - 2 - Two decimal places (step=“0.01”): allows 150.50, 99.99 (perfect for currency) - 3 - Three decimal places (step=“0.001”): allows 3.141, etc. - Omit for any number of decimals

Visual result with all enhancements:

Input field shows: $ 150000.50
Below shows: 150,000.50  (when comma_separated: true)

Note: The prefix field supports variable substitution (e.g., "prefix": "{child1name}:")

2. multiopen - Multiple inputs with labels

{
    "question_id": "hours_spent",
    "type": "multiopen",
    "query": "Hours per week spent on:",
    "prefixes": [
        "Helping {child1name} at {child1school}",
        "Helping {child2name} at {child2school}"
    ],
    "datatype": "number",
    "required": true
}

Note: For rating/satisfaction questions, consider using multilikert instead of multiopen with numbers.

3. singleselect - Radio buttons (one choice)

{
    "question_id": "preference",
    "type": "singleselect",
    "query": "Who needs more support?",
    "values": ["{child1name}", "{child2name}", "Both equally"],
    "datatype": "text",
    "required": true
}

With image (displays options horizontally):

{
    "question_id": "diagram_question",
    "type": "singleselect",
    "query": "Based on the diagram above, which option is correct?",
    "image": "images/diagram.jpg",
    "values": ["Option A", "Option B", "Option C"],
    "datatype": "text",
    "required": true
}

Note: When image field is provided, a single image displays above the question, and answer options are arranged horizontally. Otherwise, options display vertically without an image.

4. multiselect - Checkboxes (multiple choices)

{
    "question_id": "factors",
    "type": "multiselect",
    "query": "Which factors matter? (select all)",
    "values": ["Ability", "Effort", "Interest", "Future potential"],
    "datatype": "text",
    "required": true  // Note: multiselect always validates as true
}

With image (displays options horizontally):

{
    "question_id": "identify_items",
    "type": "multiselect",
    "query": "Based on the image above, which items do you see? (select all that apply)",
    "image": "images/scene.jpg",
    "values": ["Tree", "House", "Car", "Person"],
    "datatype": "text",
    "required": true
}

Note: When image field is provided, a single image displays above the question, and answer options are arranged horizontally. Otherwise, options display vertically without an image.

5. grid - Table with radio buttons per row

{
    "question_id": "scenarios",
    "type": "grid",
    "query": "For each opportunity, who would you choose?",
    "prefixes": [
        "Extra tutoring",
        "Summer camp",
        "Music lessons"
    ],
    "options": [
        ["{child1name}", "{child2name}"],
        ["{child1name}", "{child2name}"],
        ["{child1name}", "{child2name}"]
    ],
    "required": true
}

6. mpl - Multiple Price List (with automatic logic)

Same structure as grid, but selecting option in row k automatically:

  • Selects first option for rows 1 to k-1
  • Selects second option for rows k+1 onwards
{
    "question_id": "price_list",
    "type": "mpl",
    "query": "Would you accept each offer?",
    "prefixes": ["$10", "$20", "$30", "$40"],
    "options": [
        ["Yes", "No"],
        ["Yes", "No"],
        ["Yes", "No"],
        ["Yes", "No"]
    ],
    "required": true
}

7. matrix - Table with radio buttons (rows with row_id)

Similar to grid, but uses rows with row_id and text fields, and columns instead of options. Returns object with row_id keys.

{
    "question_id": "wtp_matrix",
    "type": "matrix",
    "query": "Would you pay each amount for an extra session?",
    "rows": [
        {"row_id": "100", "text": "Pay 100 pesos"},
        {"row_id": "150", "text": "Pay 150 pesos"},
        {"row_id": "200", "text": "Pay 200 pesos"}
    ],
    "columns": ["Yes", "No"],
    "datatype": "single_per_row",
    "required": true
}

Note: The matrix type includes column headers in the table. Use this when you need structured output with specific row identifiers.

8. plaintext - Display text only (no input)

{
    "question_id": "instructions",
    "type": "plaintext",
    "text": "Next, we'll ask about {child1name} at {child1school}."
}

9. likert - Single Likert scale

{
    "question_id": "satisfaction",
    "type": "likert",
    "query": "How satisfied are you with {child1name}'s school performance?",
    "prefix": "Rate your satisfaction level",
    "min": 1,
    "max": 7,
    "required": true
}

10. multilikert - Multiple Likert scales with same range

{
    "question_id": "child_ratings",
    "type": "multilikert",
    "query": "Rate each child on the following aspects:",
    "prefixes": [
        "{child1name}'s academic performance",
        "{child1name}'s social skills",
        "{child2name}'s academic performance",
        "{child2name}'s social skills"
    ],
    "min": 0,
    "max": 10,
    "required": true
}

11. consent - Consent checkbox with text

{
    "question_id": "consent_form",
    "type": "consent",
    "query": "I agree to participate",
    "text": "<h5>Study Title</h5><p>Detailed consent information...</p>"
}

Common Fields

  • question_id: Unique identifier (required)
  • type: Question type (required)
  • query: Main question text (required for input questions)
  • datatype: “text” or “number” (for input questions)
  • required: true/false (defaults to false)
  • values: Array of choices (for select questions)
    • Supports variable substitution - resolved values are stored (e.g., "{child1name}" becomes "José")
  • image: Single image URL (for singleselect/multiselect; displays image above question with horizontal options)
    • Relative paths (e.g., "image.png") are loaded from the frontend/surveys/ directory
    • Absolute URLs (e.g., "https://example.com/image.png") are loaded from the specified URL
    • Absolute paths (e.g., "/images/image.png") are loaded from the root of the web server
  • prefixes: Array of row labels (for multiopen/grid/mpl/multilikert)
  • options: 2D array of choices per row (for grid/mpl)
    • Supports variable substitution - resolved values are stored
  • rows: Array of objects with row_id and text fields (for matrix)
  • columns: Array of column header strings (for matrix)
  • text: Display content (for plaintext/consent)
  • min: Minimum value for scale (for likert/multilikert, defaults to 0)
  • max: Maximum value for scale (for likert/multilikert, defaults to 5)
  • prefix: For likert - descriptive text for single scale; For open - text/symbol shown before input (e.g., “$”)
    • Supports variable substitution

New fields for number inputs (type: “open”, datatype: “number”):

  • decimal_places: Optional number specifying decimal precision
    • 0 = integers only, 1 = one decimal, 2 = two decimals (currency), etc.
    • Controls HTML input step attribute for browser validation
  • comma_separated: Optional boolean (true/false, defaults to false)
    • When true, displays formatted number below input (e.g., “150,000.50”)
    • Uses Spanish (Mexico) locale formatting
    • Does not affect stored value (stores plain number without commas)

Summary of All Question Types

The survey system supports 11 different question types:

  1. consent - Consent form with detailed text
  2. plaintext - Display-only text (instructions, section headers)
  3. open - Single text or number input (with optional prefix, decimal control, and comma formatting)
  4. singleselect - Radio buttons (single choice)
  5. multiselect - Checkboxes (multiple choices)
  6. multiopen - Multiple labeled inputs
  7. grid - Table with radio buttons per row
  8. mpl - Multiple Price List with automatic selection logic
  9. matrix - Table with radio buttons using row_id structure
  10. likert - Single Likert scale (1-5, 1-7, 0-10, etc.)
  11. multilikert - Multiple items with same Likert scale

Recent Enhancements

Variable Substitution in Stored Answers (2025)

Variables in answer choices are now resolved and stored with their actual values:

Before: Database stored "{child1name}" as the answer After: Database stores "José" as the answer

This applies to all question types that use variables in values, options, or other answer fields.

Enhanced Number Inputs for “open” Questions (2025)

Three new optional fields for number inputs:

  1. prefix - Display text/symbol before the input
    • Example: "prefix": "$" shows a dollar sign before the input
    • Supports variable substitution: "prefix": "{child1name}:"
    • Creates a Bootstrap input-group for professional styling
  2. decimal_places - Control decimal precision
    • 0 = integers only (age, count, etc.)
    • 2 = two decimals (currency, prices)
    • 3 = three decimals (precise measurements)
    • Controls HTML5 step attribute for browser validation
    • Mobile devices show appropriate numeric keyboard
  3. comma_separated - Display formatted number
    • When true, shows formatted number below input field
    • Example: User types 150000.50, display shows 150,000.50
    • Uses Spanish (Mexico) locale formatting
    • Stored value remains unformatted (no commas in database)
    • Updates in real-time as user types

Example combining all three:

{
    "question_id": "price",
    "type": "open",
    "query": "¿Cuánto estaría dispuesto a pagar?",
    "datatype": "number",
    "prefix": "$",
    "decimal_places": 2,
    "comma_separated": true,
    "required": true
}

Visual result:

Input shows:  $ 150000.50
Below shows:  150,000.50
Stored as:    150000.5 (plain number)

Unicode Support (2025)

Spanish characters (á, é, í, ó, ú, ñ) are now stored correctly in the database instead of as escape sequences like \u00e1.
